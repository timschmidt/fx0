## Ownership and profile separation

The factory borrows the actual `_cleanup_child`, `spawn` and `close` method
code/closures from the qualified native ownership factory. These methods have no
native-profile callbacks or `super()` dependency. The passive class inherits
only the original passive transport class; no native-specific class enters its
method resolution order. Passive preflight, serial observation, 400-second
observer wait, return checks and RFSA worker remain passive callbacks.
The tests check this code identity and inheritance directly.

A child is owned before log close/journal persistence. Failed spawn persistence
triggers bounded termination/reaping, and finalization attempts every directly
owned child even if persistence or another cleanup fails. Child roles cannot
replace existing handles. Cleanup receipts cannot overwrite an earlier execution
deadline. The shared port lock stays held through finalization, and failed
cleanup cannot emit terminal success. Expired observer waits reject even if the
actual child exits zero. Transfer/observer/normal-return execution limits remain
180/400/45 seconds plus the runtime's bounded termination/kill grace.

RFSA/local publication acceptance requires successful owned observer completion
without deadline expiry, terminal/closed serial observation, one attempted worker,
complete successful worker status, exact six publication/RFSA/withdrawal markers
bound to a new RAM boot, expected linked r1 notes/release, and the observed native
USB generation matching the independently verified return. Missing generation
data cannot compare equal through absent values. Native return alone is not
worker acceptance. Fresh physical display/touch checks remain separate.

The original readback-before-one-BOOT and no-retry-after-intent policies still
apply. A parent deadline cannot authorize USB reset. This source change starts
no firmware, loads no phone module and qualifies no physical RFSA/USB/return
operation by itself. Hardware responses in the public fixtures are substituted;
the disposable subprocesses and their owned terminal receipts are real.
