# Alternate r59 RAM image encoding

The r59 XZ3 image timed out after 524,288 confirmed download bytes. The next
16,384-byte host request lies inside the compressed kernel stream. Its
completion count is unknown. The transfer stopped before complete readback
and the handset returned to native r50. The timeout therefore gives evidence
about staging and cannot establish how r59 would boot.

The XZ4 candidate changes that stream. It uses the same ARM BCJ filter, LZMA2
`lp=2`, `lc=2`, 128 MiB dictionary and CRC32 as the previous encoding. The
relocated decompressor link and recorded assembly command reproduce the XZ3
zImage before the preset changes. The new zImage also reproduces exactly
through a second assembly and link. Only the compressed payload object is
reassembled. The signed package, source kernel and original scratch are
preserved in their existing paths.

The final image is 6,330,368 bytes with SHA-256
`6ccb35ccfc6637902951314f47b61a9925c33eb5b8d163ec1c3b0db8fe1c7020`.
The first unconfirmed host frame changes 16,325 of 16,384 bytes. The original
frame sequence is absent from the new image. The appended DTB and compressed
initramfs are byte-identical, preserving all fourteen entries and the original
180-second timer. The Android header changes only its kernel size and checksum.
This produces a distinct staging candidate. Its physical transfer reliability
and the cause of the USB timeout remain open.

The [ARM harness](arm-zimage-decode.c) links the exact r59 `decompress.o` and
`string.o`. Under isolated ARM QEMU, the original signed encoding, XZ3 and XZ4
all produce the same 21,201,060 bytes, SHA-256
`8a7cadb571406306d4fb90de0b7dc2316d0b0160804c38fd879c658de48e2892`.
The harness calls the real single-call decoder with a 64 KiB scratch area.
Python and the retained XZ tool independently reproduce the same runtime
Image. The runtime notes, built-in certificate and module ABI therefore
remain those of r59. Full boot relocation and on-device execution still
require a physical trial.

The local build scratch is `local/nfc-r59-transfer-encoding-01`. Its scripts
relink using the retained Alpine tools mounted read-only, execute the decoder
under QEMU and build the Android image with the existing image builder. The
following command independently checks the candidate against the failed image.

```sh
base=local/nfc-r59-transfer-encoding-01
PYTHONDONTWRITEBYTECODE=1 python3 diagnostics/ram-transfer/check-reencoded-image.py \
  --reference local/nfc-open-teardown-startup/fx0-nfc-r59-moduleless-xz3-ram.img \
  --reference-sha256 0fff381eeb94f8ce8673404a3fb5d896e4767c0d9fb2eb3a942b00cb70980dce \
  --candidate "$base/fx0-nfc-r59-moduleless-xz4-ram.img" \
  --reference-piggy "$base/xz3-piggy.bin" --candidate-piggy "$base/xz4-piggy.bin" \
  --runtime "$base/work/arch/arm/boot/Image" --offset 524288 --chunk 16384 \
  --output local/r59-xz4-image-recheck.json
```

Six negative checks cover changed DTB, initramfs or header, a wrong packed
stream, unchanged frame bytes and a frame outside the kernel stream. The
one-use trial directory pins the new image hash and current native boot.
Its offline entry checks reject missing, pending or mismatched UI evidence
before importing the phone client. The matching synthetic receipt reaches
the import boundary. Physical staging still requires a current display/touch
baseline, fresh preflight, terminal successful transfer and exact readback.
The existing payload-free journal records the physical attempt when it runs.

## Physical staging result

The XZ4 image completed the 16 KiB write at the original XZ3 stall offset of
524,288 bytes. It then completed eight more writes and timed out at offset
671,744. Both attempts used the same port, installed lk2nd identity, 16 KiB
host requests and 5 ms pacing. The new journal records 41 full payload
writes. The failed OUT request lasted about 30.29 seconds and its delivery
count is unknown. The host kernel journal confirms high-speed enumeration
and records the later recovery reset. It contains no matching port or xHCI
messages during the timeout. A USB packet trace would be needed to inspect
the unconfirmed request.

The stage and transfer processes exited before the identified USB reset
and normal reboot. The r50 boot hash, installed files, services, 1.15 V APC
target and UPower r5 recheck passed. A transient SSH timeout interrupted the
first postflight, so the read-only checks were resumed on the same boot.
