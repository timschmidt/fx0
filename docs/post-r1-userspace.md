# Userspace qualification after the persistent r1 kernel

The accepted phone baseline is the installed Linux 6.18.63-r1 kernel,
Sxmo 1.18.1-r7 and UPower r5. Display and touch were confirmed for this
installed boot. The earlier r50 package-update plans describe historical
states and must not be replayed against r1.

A new capture retains all 6,351 earlier scope names but reads their current
bytes and metadata. It also covers the complete current boot, modules,
kernel package, APK database, APK configuration, command-line configuration,
systemd units, commit inventory and executor namespace. The result contains
7,002 paths and 701 complete directory memberships. Partial ancestor
directories carry metadata without claiming a complete child namespace.

The capture holds both exclusive FLOCK and POSIX locks on the actual APK
lock inode. Their presence is checked through /proc/locks before and after
capture. The lock file is read through the held descriptor: opening and
closing another descriptor for that inode would release this process's
POSIX locks. Runtime private keys and credential files are excluded.

All archived regular payloads, hardlink groups, nanosecond metadata and
SELinux labels are verified. The fresh full archive, manifest, empty delta
and raw boot backup have independently checked private copies on the phone
and host. Older r50 payload bytes are not reused for these backups.

The private native rehearsal restores this capture into a new chroot and
uses the actual ARM APK 3.0.8, native kernel and existing public trust keys.
The live system is read-only inside the unit, block devices are hidden,
networking is isolated, cgroup migration is prevented and resources are
bounded. Reused runtime libraries are compared with current native files
before execution. Normal commit hooks and BusyBox triggers remain enabled.

The intended forward operation is a signed local-repository upgrade of
treescan alone. It must preserve world and the other 774 package identities,
including the held r1 kernel. Both the r1 candidate and exact r0 rollback
archive must pass native signature verification.

Treescan's own upgrade has a timing detail: APK's pre-commit hook runs the
old r0 executable before replacement. That inventory retains incorrect ARM
timestamps. After the upgrade, the managed procedure explicitly invokes the
unchanged existing pre-commit hook again. The resulting unit identities,
types and timestamps are compared with independent filesystem metadata.
The installed executable is also checked at negative, zero, 2038 and 2100
timestamps, with recursion, spaces, symlinks and missing-directory failure.

The exact signed r0 downgrade runs through normal APK hooks before
file-backed recovery. Its pre-commit inventory is generated by the still
installed r1 executable. Normal downgrade alone therefore does not establish
exact recovery of the original inventory, world or file metadata. Recovery
must wait for every owned hook to exit, then verify all 7,002 captured paths,
701 memberships, hardlinks, labels, original package identities and the
complete private namespace.

The first final namespace guard stopped on a cache copy of the exact r0 APK
that normal APK installation created inside the owned fixture cache. The
failed result and fixture were retained. After the unit and all descendants
exited, a separate bounded verifier independently checked all recovered
metadata and payloads, authenticated the one cache file, and removed that
owned copy. It derived the complete expected namespace from the authenticated
baseline, runtime closure and explicit harness files. The corrected
verification did not replay any package transaction. Completion is supported
by that verifier's actual PID1 journal and outside-unit postflight, rather
than by relabeling the first failed service.

The independent verifier also initially rejected an expected absent path
because its parent was absent. That verifier error was harvested before
correction; no recovery bytes changed. Focused checks cover absent parents
and rejection of dangling symlink and non-directory ancestors. A later
namespace comparison exposed an omitted harness entry: APK's private log,
created by index loading before the first transaction. Its regular file
type, owner, mode, size, single link, content hash and transaction entries
were verified and added explicitly. These failed attempts remain part of
the evidence.

The manifest and evidence accompanying this document report actual
completion and any failed attempts. A private chroot rehearsal qualifies
that procedure in its stated scope. Live activation still needs a separate
qualified controller; the generic file rollback helper deliberately refuses
the live root. The signed treescan candidate and remaining stable updates
stay uninstalled until those live transaction and recovery gates pass.
Audio testing is excluded, and complete hardware and reliability acceptance
remains open.
